🎨 Mejoras visuales SERFAGAB

Explicación simple de lo que se hizo y cómo se aplicó al proyecto, para que todo el equipo entienda.

✅ Primero, lo importante: el proyecto sigue cumpliendo lo que pidió el profesor. El frontend sigue siendo ASP.NET Core MVC y la API sigue siendo ASP.NET Core Web API. Solo se cambió la apariencia (colores, menú, tarjetas), no la lógica ni la arquitectura.

¿Qué problema había?

El proyecto funcionaba bien, pero las páginas se veían "básicas" (estilo por defecto de Visual Studio).

Se adaptó el estilo de una plantilla de referencia (PROYECTO_LP2_GRUPO_B) para que el sistema se viera más profesional y moderno: tema oscuro, menú lateral, tarjetas, colores corporativos.

¿Qué se cambió?

Se modificaron solo archivos de presentación dentro de Consumo. No se tocó la lógica ni la WebApi.

¿Cómo se aplicó? (paso a paso)

Se trabajó primero en una copia de prueba aislada (sin tocar el repositorio real), para probar los cambios sin riesgo de romper nada.
Se probó todo en esa copia: que el login funcionara, que los listados mostraran datos y que las tablas ordenaran bien.
Cuando ya se verificó que estaba bien, se copiaron los archivos al proyecto real, manteniendo la misma estructura de carpetas:
  • Consumo/ProyectoGrupalDSWI_Serfagab_CS/Views/ (las páginas)
  • Consumo/ProyectoGrupalDSWI_Serfagab_CS/wwwroot/css/ (estilos e imagen)
Se recompiló y se probó el proyecto Consumo (la WebApi debe estar corriendo aparte, porque provee los datos).
Se subió el cambio al repositorio con git (commit y push).

⚠️ Detalles que debes saber para no romper nada

  • La carpeta wwwroot no puede renombrarse: es el nombre obligatorio de ASP.NET Core para servir archivos estáticos (CSS, JS, imágenes).
  • Al reemplazar Views, no borres _ViewStart.cshtml ni _ViewImports.cshtml (están en la raíz de Views). Sin ellos las páginas no se renderizan.
  • Para ver los cambios al navegar, usa Ctrl + F5 (refresco forzado) para que no quede la versión guardada en caché del navegador.
  • Deben correr los dos proyectos: la WebApi (puerto 7229) y Consumo. Consumo pide los datos a la WebApi.

🛠️ Para correr el proyecto (para cualquier compañero)

  1. Clona el repositorio.
  2. Abre la solución DSWI_ProyectoGrupal.sln (o los proyectos por separado).
  3. Ejecuta primero la WebApi, luego Consumo.
  4. Abre el navegador en la URL de Consumo y haz Ctrl + F5.
  5. Ingresa con las credenciales del sistema (ej. admin).
Resumen: los cambios son 100% visuales y de presentación. No afectan la lógica de negocio, la base de datos ni la API. Cumple con el requisito del profesor (front en .NET MVC, API en .NET).
